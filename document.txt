1. Python Crash Detection Engine (gate.py, gate_v2.py)
This is the core detection logic - a motion gate + tracking/collision pipeline.
Key Classes
BaselineState (gate.py:55-113)
Manages adaptive threshold calibration per lighting mode (day/twilight/night).
Fields:
- scores - Rolling window of physics scores
- median, mad - Robust statistics
- threshold - Dynamic trigger threshold
- calibrated - Whether baseline is established
- calibration_mode - "frozen" or "adaptive"
- freeze_until - Timestamp preventing learning during alerts
- consecutive_above - Persistence counter
Methods:
- update_baseline(window_size) - Recomputes median/MAD from recent scores
- compute_threshold(k_mad) - Threshold = max(median + k*MAD, 99th percentile)
- add_score(score) - Adds clipped score to window
- check_trigger(score, threshold) - Returns true if score > threshold for N frames
- is_frozen() - Checks freeze timer
- trigger_freeze(seconds) - Prevents learning during active events
DayNightClassifier (gate.py:115-164)
Classifies frames by brightness with hysteresis.
Thresholds: day>80, night<50, twilight in between
Hysteresis: 10 units, persist 60 frames before mode switch
Forced mode: Override via constructor
AutoThresholdManager (gate.py:166-300)
Manages per-mode baselines, loads/saves JSON snapshots.
Key parameters:
- camera_id - Baseline namespace
- k_mad=2.0 - Threshold multiplier
- persist_frames=7, persist_window=12 - Trigger persistence
- window_size=9000 - Score history (5 min at 30fps)
- calibration_target_frames=9000 - Frames before first calibration
Update flow: (line 258-299)
1. Classify frame → get mode baseline
2. If alert/collision/frozen → skip learning, return current threshold
3. If not calibrated or adaptive → add score to window
4. If enough samples and not calibrated → calibrate (median, MAD, threshold)
5. If calibrated & adaptive → adapt threshold periodically
6. Check trigger persistence
7. Auto-save baselines every 5 seconds
StabilityMonitor (gate.py:312-361)
Verifies baseline has stabilized before allowing early exit from calibration.
Criteria:
- Min 9000 frames, 8+ snapshots over 3000-frame window
- Threshold variation < 0.008
- Median drift < 0.015, MAD drift < 0.015
- MAD not too small, threshold not at bounds
MotionGate (gate.py:363-421)
Stage 1: Frame differencing physics score + adaptive threshold.
Physics score: absdiff(prev_gray, curr_gray) > 25 → pixel ratio × 10
Smoothing: Rolling mean over physics_window frames (default 5)
Alert cooldown: 90 frames after trigger
FeatureExtractor (gate.py:560-1013)
Stage 2: YOLO detections → tracking + pair features.
Tracking:
- Hungarian-like greedy assignment by normalized bottom-center distance
- Max miss frames = 15
- Predicts positions via constant velocity when no detection
- Distinguishes predicted vs observed tracks
Motion states: UNKNOWN → MOVING/STATIONARY → STOPPED → PARKED
- EMA speed, hysteresis on enter/exit moving
- Parked: never moved + stationary > 150 frames
Pair features (only updated when BOTH tracks have fresh observations):
- Normalized distance, closing velocity, TTC, min separation
- Conflict: closing > 0.015, t_closest ≤ 12 frames, min_sep ≤ 0.85
- IoU tracked but diagnostic only
- Impact: decel event + heading change within 5 frames
Optical flow: Sparse LK on detection ROI → flow angle std as turbulence measure
RuleClassifier (gate.py:1016-1147)
Stage 3: Collision verdict from trajectory conflict + temporally linked impact.
Pair collision criteria:
- Fresh observations on both tracks (max_pair_age=1 frame default)
- Not both stationary/parked
- Closing velocity ≥ 0.025
- Recent conflict (age ≤ 5 frames), min_sep ≤ 0.85
- Impact signature on at least one vehicle:
- Decel event (speed drop ≥ 45% from ≥ 0.05)
- OR heading change ≥ 0.55 rad + impact
Voting: k-of-m (2 of 4) over recent frames per pair/track
Cooldown: 30 frames per track
Rollover detection (moving vehicles only):
- AR oscillation ≥ 0.6, ≥ 4 peaks, heading P90 ≥ 0.9
gate_v2.py - Enhanced Stage 1
- EMA smoothing on physics score (α=0.4)
- X-of-Y persistence (7 of 12) instead of consecutive
- Raw spike escape: raw ≥ threshold + max(0.05, 10% threshold)
- Exposes trigger components for rendering

5. Data Flow
Crash Detection Pipeline (Edge → Server → Client)
Android Phone (Edge Device)
    │
    ├── Camera frames → YOLO detection
    ├── Frame differencing → physics_score
    ├── MotionGate.check(frame) → GateResult (triggered, threshold, score)
    │
    ├── FeatureExtractor.update(detections, frame)
    │     ├── Tracks: predict/update positions
    │     ├── Pairs: conflict + closing velocity + impact
    │
    ├── RuleClassifier.predict(features, pair_features)
    │     └── "collision" / "rollover" / "normal"
    │
    └── If collision → POST /api/incidents/report
              │
              ▼
Backend Server
    │
    ├── Incident.create(PENDING_VERIFICATION)
    ├── io.emit('incident:new', incident)
    ├── io.emit('dashboard:update')
    │
    ▼
Web Client (Socket.io)
    │
    ├── Dashboard: fetchStats() → updates counts + plays audio
    ├── LiveIncidents: fetchIncidents() → new card appears
    ├── EmergencyDispatch: fetchData() → queue updated
Heartbeat Flow
Android App (periodic)
    │
    ├── POST /api/devices/:deviceId/heartbeat {status, lat, lng}
    │
    ▼
Server
    │
    ├── EdgeDevice.lastHeartbeat = now
    ├── If cameraId linked → Camera.lastHeartbeat = now, status=ONLINE
    ├── getEffectiveStatus() compares now - lastHeartbeat < 5min
    ├── io.emit('device:update', device)  (or device:online/offline)
    ├── io.emit('dashboard:update')
    │
    ▼
Client
    │
    └── EdgeDeviceManagement: device card updates in real-time

7. Key Design Decisions
Motion Gate (Stage 1)
- Frame differencing over optical flow for speed
- Adaptive per-mode baselines handle day/night/twilight
- Frozen calibration prevents traffic from raising threshold
- X-of-Y persistence (v2) reduces false positives from transient motion
Tracking (Stage 2)
- Bottom-center association more stable than bbox IoU for traffic
- Scale-normalized distance works without homography
- Predicted tracks marked - never treated as fresh observations
- Pair features only on fresh-fresh pairs - avoids stale-vs-fresh artifacts
Collision Logic (Stage 3)
- Trajectory conflict + temporal impact - not just overlap
- Moving vs stationary/parked supported
- Voting over time - single-frame glitches don't trigger
- Rollover detection separate from collision
Server
- Public incident reporting - Android app doesn't need auth
- Socket.io for real-time - no polling
- Heartbeat-based online status - 5min timeout
- Status machine on Incident/Unit enforces valid transitions

10. Testing Checklist
- Gate calibration: stable threshold after 9000 frames of normal traffic
- Day/night/twilight mode transitions with hysteresis
- Motion state machine: MOVING→STOPPED→STATIONARY→PARKED
- Pair conflict: approaching vehicles, crossing paths, rear-end
- Collision veto: both stationary, insufficient closing, no impact
- Heartbeat timeout: device → OFFLINE after 5min
- Socket reconnection: client survives server restart
- Auth: JWT expiry, protected routes redirect
- Dispatch flow: VERIFIED→DISPATCHED→RESPONDING→RESOLVED
- Unit availability: can't dispatch UNAVAILABLE unit
